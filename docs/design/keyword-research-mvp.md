# DocLens 桌面端关键词研究需求规格

草案 0.4 · 首版范围已确认 · 产品默认值与验收指标供评审

## 1 产品目标与范围

DocLens 面向需要阅读多篇论文或实验报告的学生与研究人员。用户在 Windows 本地项目中导入文档，输入关心的词，核对各篇如何描述它，再把判断和来源一起保存。分享接收者可以离线阅读报告或打开项目复核证据。

首版由**用户提出要比较的词**。输入数据集名、方法名或其他原词后，应用在提取正文中定位并并列展示命中段落。用户选两段做离线 Diff，需要解释用途时主动调用联网 AI。首版覆盖「给定术语后找共同点和区别」。自动发现用户未输入的共同数据集或方法属于另一项能力，暂未纳入。

- P0 为 Windows 本地项目、四格式导入、原词查找、片段 Diff、按需联网 AI、章节与证据导航、关联笔记、Markdown 导出和离线共享。AI 是首版交付能力，用户可以只使用离线流程。
- P1 为同义表达与主题的语义搜索。整篇版本差异比较可后续作为辅助工具评估。旧版可独立查阅。
- P2 为 OCR、扩展格式、复杂文档的原貌定位和自动发现共同实体。实时协作、云同步、内置或随应用安装的本地模型、矩阵和独立跨文档搜索入口不属于首版。

新版延续 DocLens 仓库和桌面工程。现有解析、文本定位、Diff、项目存储、导出以及 AI 确认与引文验证机制可按新版流程复用。[旧版 0.6.0 多文档研究规格](multi-document-mvp.md)和[矩阵版桌面原型需求](desktop-prototype/需求规格.md)供历史对照。

## 2 用户旅程与界面

1. 在「项目与文档」创建项目、批量导入、检查逐份解析结果，再选定参与研究的文档。
2. 在「关键词比较」输入一个或多个词。点选左侧词条后，右侧按文档展示命中段落、位置和高亮。用户可直接阅读、切换命中或展开正文。
3. 从两篇文档各选一个片段，使用「本地文本比较」。需要解释用途时，使用同页的「AI 分析用途」，检查待发送片段后确认。
4. 从任一片段或 AI 引文跳到正文，可选择多篇来源加入同一条「研究笔记」。保存项目后可接着研究。
5. 从「导出与共享」制作 Markdown 报告或共享包。接收方按交付方式阅读报告或在 DocLens 打开项目。

主导航包含「项目与文档」「关键词比较」「研究笔记」「导出与共享」。章节导航与证据阅读随正文显示。关键词页保留当前关键词、文档范围及两侧片段选择。多篇文档先分组呈现，再选任意两篇并排。两种比较功能共享搜索范围，AI 的实际提交范围在发送预览中单独确认。

## 3 P0 功能需求与逐项验收

### R1 本地项目与文档

- 支持创建、命名、打开、保存和另存项目。首次运行可以新建项目或打开本地项目。文档库可勾选比较范围、移除文档，并显示格式、解析状态与警告。移除前告知受影响的笔记引用。
- 批量导入 PDF、DOCX、Markdown（`.md`、`.markdown`）和 TXT。MD/TXT 采用 UTF-8，可带 BOM。PDF 需要可提取文字。纯扫描、加密、损坏、不支持的编码或超限应给出清晰原因。DOCX 正文和可提取表格文字可用，公式、图像或复杂排版缺失时显示警告。
- 每个文件单独显示成功、部分提取、重复或失败。部分提取只对已有文本提供查找，并一直保留警告。没有可用文本的文件不参与比较。按文件内容判断重复。同名但内容不同的文件分别保存，并在列表中区分。
- 保存提取正文、结构、可用的位置和导入提示。外部原文件改动后，项目中的快照仍指向导入时保存的内容。重新导入不同内容形成独立文档，旧引用继续指向旧快照。移动项目后可直接读取已保存的提取正文。

**验收 R1**：一批文件含四种有效格式、一个重复副本、一个同名不同内容文件和一个损坏文件。成功项可用，重复不增加文档，同名文件可区分，损坏文件有独立错误。另测一次纯扫描 PDF 与一份部分可提取 PDF。移动已保存项目并让原路径不可用，仍能打开正文和笔记。

### R2 用户关键词与多文档片段对照

- 用户可添加、修改和删除多个关键词。每个词独立执行，默认在当前项目全部可读文档中查找，也可只选指定文档。拒绝空词，同一匹配规则下的重复词保留一条。
- 原词查找基于提取正文。输入去首尾空白，英文字母忽略大小写，词内部的空格、数字和标点按字面保留。英文或数字术语的边界不跨入相邻的英文字母、数字、下划线或连字符。`ResNet` 命中 `resnet`，`ResNet50` 和 `ResNet-50` 则分别输入。`CIFAR-10` 不匹配 `CIFAR-100`。中文按连续字面匹配，例如「训练方法」不会命中仅写「模型训练流程」的段落。词或短语不跨提取块匹配。
- 一个提取段落或文本块计为一个片段。同一块内多次出现按命中次数统计，片段只列一次。列表显示命中文档数和命中片段数，单篇展开后按原文顺序展示各块及命中高亮。可打开相邻上下文。0 命中、尚未选择可读文档和部分提取分别提示。
- 关键词改名或文档范围变化后刷新命中。当前片段仍在结果内时保留选择，失效的选择清空。已作为笔记证据保存的引文本身独立于关键词列表，修改或删除词条不会改变引用位置。

**验收 R2**：断网且无 API 的情况下，比对 `ResNet`、`resnet`、`ResNet50`、`ResNet-50`、`CIFAR-10`、`CIFAR-100` 与中文同义短语的正反样例。同一段两次出现时显示一个片段、两个高亮。改变所选文档后，列表计数同步，旧笔记引用仍可打开。

### R3 本地 Diff 片段比较

- 在当前关键词下，从两篇不同文档各选一个命中块作为比较输入。正文与相邻上下文可同时阅读，Diff 以选中块的提取正文为准。缺少任何一侧时，提示选择两篇有命中的片段。多文档项目可切换任意两篇，每次比较一对。
- 两侧显示文档名和真实可用的位置。用文字与高亮区分「相同」「仅左侧」「仅右侧」「文字不同」。关键词高亮可以与差异标记区分。完全一致时显示「所选片段内容一致」。清晰标明这两段的实际文字，对相近研究主题不作自动配对，也不从 Diff 推出是否采用某个方法。
- 更换文档、关键词或命中段落后，界面按有效选择重新计算或提示重新选段。两侧差异均可跳回相应的正文范围。临时 Diff 可重算。需要长期保存的判断以笔记及引用保存。

**验收 R3**：同一关键词的两个段落分别写训练 50 轮和 100 轮，离线 Diff 突出对应数值且两侧能定位。再覆盖两段一致、只有一侧出现一句话、切换到第三篇，以及缺失一侧四种情况。未命中文档不能作为空文本与其他文档比较。

### R4 联网 AI 分析关键词用途

- 设置中可填写受支持的云端 API 地址、模型和凭据。用户主动发起分析，一次针对一个关键词。在确认界面显示服务、模型、各文档命中片段总数、哪些片段将发送、实际发送文本和附加上下文，以及任何因用户选择或上限而未纳入的片段。发送范围限定为确认内容。撤销或取消预览时不发请求。
- 结果按文档和用法呈现「本文采用」「背景或相关工作提及」「明确未采用」「无法确定」。同一文档可有多条不同的用法。只有正文清楚表示「本文未采用」时，才可作明确否定。未命中、未提交、已提交未完成、请求失败、证据不足各有独立状态。
- 每项确定的判断必须引用其所在文档中已提交的逐字片段，由应用验证文档、快照、原文范围及引文是否对应。引文有多个相同出现位置时，需定位到提交的具体块或确切区间，无法唯一定位则不接受。引文不一致或引用来源不正确时，撤下该判断，显示「无法确定」。文本一致性校验只证明来源可定位，结论中的研究主体、否定关系与实际用途需通过验收样本和用户核对。
- 每篇至少能看到命中、已选提交、已完成的片段数。应用区分部分覆盖与完成。跨文档摘要须有至少两篇的有效证据，每条比较判断均可回到出处，说明分析仅覆盖已完成的所选片段。摘要所需请求也列入发送预览。证据不足时，保留逐篇结果和原文。
- 请求超时、无网、密钥无效、服务限流、服务返回不完整、取消均显示状态。已成功结果和离线能力仍可使用。用户可主动重试未完成部分，重新预览并确认。切换关键词或分析范围时，已有结果若展示须标明原范围。AI 输出在首版作为当前会话结果，用户可将解释和已验证引文加入笔记并明确保存。

**验收 R4**：用 R2 同一词的多篇样本验证本文采用、相关工作提及、明确未采用、证据不足。检查「他人采用但本文明确未采用」不能归为本文采用。模拟错误文档、改写引文、缺漏和超时，确认提示与覆盖数字准确。取消发送预览时记录为零请求。部分成功后重试仅覆盖用户选定且重新确认的未完成片段。发布前另行使用一项已配置的真实云服务验证主流程。

### R5 原文导航与研究笔记

- 从命中片段、Diff 差异、已验证 AI 引文、目录或笔记引用可跳到对应文档和位置。Markdown 识别标题并提供可点击目录。其余格式显示可用章节、PDF 页码或段落。手动跳转与高亮针对提取正文。缺少可靠页码时显示真实可用的段落位置，无标题也可按段落阅读。
- 引用保存文档标识、快照标识、正文区间、逐字引文和可展示位置。同一句话出现多次时采用保存的区间定位。来源移除或区间失效时，保留已保存的引文和笔记正文，标记「来源不可定位」，禁用该引用的跳转。
- 支持新增、编辑、删除 Markdown 笔记，允许无引用，也可附同一篇或多篇的多条引用。用户可修改自己的判断和增减引用。用户可将 AI 建议加入笔记正文，保留 AI 来源标记并可自行编辑。
- 保存项目后，文档快照、解析状态、关键词列表、文档范围、笔记和引用在重开时恢复。本地命中与 Diff 可按当前输入重新计算。未保存时给出状态，关闭、切换项目或退出前提供保存、放弃或取消选项。保存失败显示原因，并保留可重试的编辑内容和上次保存的文件。

**验收 R5**：建立包含两篇引用的笔记，涉及重复句和含中文及 emoji 的段落。保存后重开，逐条跳到原来那一处。移除一篇后重开，剩余引用仍可点击，失效引用与笔记正文仍可阅读。验证未保存退出、模拟保存失败和再次保存。单独检查应用内 Markdown 章节导航。

### R6 Markdown 导出、离线共享与旧版兼容

- Markdown 报告包含项目名称、关键词、所选笔记及其来源引文，显示提供者可用的文档名、章节、页码或段落。报告内目录和引文可通过锚点链接，纯文本方式也可阅读。默认不加入整篇提取正文。尚未加入笔记的临时 AI 输出和 Diff 结果不随报告导出。
- 离线共享包包含 Markdown 报告和可重开的版本化项目快照，快照含已选文档的提取正文、结构、关联笔记与引文。导出前显示拟分享的文档、笔记、提取正文和原文件清单。原文件默认不附带，只有可用且明确勾选才加入。选择范围外的引用不自动带入文档，预览会指出其在接收端不可跳转。应用写入的包元数据不包含 API Key、模型配置或本机绝对路径。
- 接收者可离线打开共享包为独立项目并「另存为」，引用可定位到随包提供的文本快照。校验格式版本、包大小、重复条目、文件路径、快照结构与引用有效性。包内标记为不可定位的引用可以保留引文。声明可定位却找不到对应快照或区间的引用属于包错误。未知或无效格式给出明确说明，保留当前打开的项目。
- 0.6.0 的受支持本地项目与共享包可读入，保留文档快照、笔记及可验证的旧引用。首次保存新版格式使用「另存为」。旧引用如无法可靠映射，保留笔记正文并标记来源不可定位。对原文件和项目格式的兼容以旧版样例验收。

**验收 R6**：报告单独拷贝到另一目录仍可阅读，内部链接在约定的 Markdown 阅读器中可点。离线在干净 Windows 环境打开两份共享包，分别含原文件和不含原文件，清单与内容一致，多篇引用可定位，范围外的引用按预览标记。旧版项目文件和旧版共享包都能读入并另存，源文件未被覆盖。未知版本或无效引用的损坏包不能替换正在打开的项目。

## 4 首版非功能要求与容量

### N1 Windows 桌面交付与可用性

交付可实际运行的 Windows x64 桌面构建，最低验收环境暂定 Windows 11 x64。优先交付可运行的便携包，安装程序形式可选。优先验证 1440×900，另测 1280×800 和 1920×1080。列表和正文可各自滚动，关键词和证据可以用键盘切换，状态与差异同时有文字提示。断网和未配置 API 时，导入、保存、查找、Diff、笔记、导出和开启共享项目均可用。

### N2 容量与响应目标

- 沿用 0.6.0 容量作为首版验收基线：单文件最多 10 MiB、提取正文最多 100,000 个 Unicode 码点，PDF 最多 300 页。项目最多 50 份文档，提取正文合计最多 100 万码点。DOCX 解包限制沿用现有解析器。项目文件、共享包及其解包总量上限为 100 MiB。每项目最多 500 条笔记，每条正文 20,000 字符。
- AI 建议上限沿用现有服务流程的数量级：每次任务最多 20 个命中块，每批最多 4 个块，每批发送的片段与上下文最多 12,000 字符，每个任务合计最多 60,000 字符，每批最长等待 120 秒。供应商如有限额更低，按较低上限处理。提交前显示选取和排除范围，超限时可以缩小选择。
- 暂定性能目标以 Windows 11 x64、4 核 CPU、16 GB 内存、SSD 的参考环境实测。已载入 20 篇、每篇约 20,000 字符的 MD/TXT 项目后，单词首次查找 2 秒内显示计数及首批结果。两个各 2,000 字符的片段 Diff 1 秒内显示。缓存正文的证据跳转 300 毫秒内反馈。以 10 次测试的第 9 快结果判断是否达标，并记录样本、设备、耗时和观察到的最慢值。以上为验收目标，发布前可根据实测复核。
- PDF/DOCX 和联网 AI 的耗时单独记录。耗时操作使用可操作的进度与取消。取消后的完成项、待处理项和未保存状态要能分辨，不因部分失败丢弃此前成果。

### N3 数据保护与保存一致性

本地工作流不自动发送文档。发往云服务的内容只取用户确认的片段、必要上下文和分析所需信息。应用把文档正文与模型输出视作数据，禁止其中的指令更改应用操作或发送范围。AI 判断只引用验证通过的来源。密钥由系统提供的账户保护能力保存，界面按需遮蔽，不进入项目、共享包或日志。保存失败须保住上一份可读文件，不留半写入结果。导入包的内容在校验完成后才进入工作区。

## 5 最小发布验收

使用合成文档作为固定验收样例，明确记录预期结果。至少包含以 `ResNet` 为关键词的 A 篇本文采用、B 篇介绍他人研究、C 篇明确未采用，以及 D 篇解析不完整且上下文不足。A、B 另含同词、多次命中和可核对的 `50` 与 `100` 数值差异。保留一份包含中文、emoji 和重复句的样本检查定位。

1. **离线主流程**。在可分发的 Windows 构建中新建项目，批量导入，查找两个词，切换文档，Diff 找出数值差异。选两条不同文档的证据写入笔记，关闭再开并核对跳转。
2. **联网分析**。同一份项目里确认发送范围，验证四种用法、引用定位和覆盖数字。模拟至少一次中途失败及重试，再以真实配置检查一次端到端的云服务调用。
3. **交付给另一位用户**。导出 Markdown 和两份带与不带原文件的共享包。接收端不使用作者机器的路径，断网阅读、重开共享项目、复核两篇引用。独立验证旧版兼容和无效包处理。
4. **发布记录**。各项记录样例、环境、操作和预期与实际结果。R1–R6 及 N1–N3 逐项判定通过、失败或待验证。未通过的首版验收项在发布前处理，暂缓项写明影响及后续版本安排。

## 6 补全时采用的产品默认值
