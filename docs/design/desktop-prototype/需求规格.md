# DocLens 桌面端需求规格

版本 1.0 · 2026-11-24 · 需求与设计基线

## 1 产品目标与需求依据

DocLens 面向需要阅读多篇研究文档的学生、教师与研究人员，帮助用户把“发现相同内容”推进到“有证据的比较、记录与共享”。核心交付是可追溯的对照矩阵和笔记：任何比较结论都应能回到对应文档、章节及原文片段。

需求依据为本次明确指令、引用对话中教师提出的四项需求，以及仓库 README 与 docs/design/multi-document-mvp.md。引用对话仅提供有限预览，不推测未展示的历史回复。现有仓库已描述双版本比对和多文档研究；本规格用于独立桌面 UI 设计和后续开发验收，不代表此 HTML 原型已实现正式解析、分析或生产存储。

目标平台为 Windows/macOS 桌面生产力环境，优先 1440×900，支持 1280 宽度和 1920 宽屏。移动端与实时协作不在本轮范围。正式应用的 macOS 打包、原貌转换依赖与兼容性需单独验证，不能从网页兼容性推导。

成功指标：用户能在同一项目导入多篇文档，按数据集和方法比较，核对至少一项共同点和一项区别，保存关联证据的笔记，并导出可离线阅读的材料。比较不能把“被引用”自动认定为“实际使用”，也不能把“未发现”认定为“不存在”。

## 2 用户与核心问题

学生整理文献综述，需要知道哪些论文研究了相近问题、采用了相同数据或方法，减少反复切换窗口。教师审阅比较笔记，需要能快速验证学生的判断依据。研究人员复核两个文档版本，需要保留原有逐项差异定位能力。

用户的主要困难是来源丢失、术语别名混淆、引用与使用混淆、结论无法复核，以及导出后链接依赖作者电脑路径。产品优先解决这些问题，而非自动代写综述或生成未经核验的学术结论。

## 3 用户旅程与信息架构

旅程 A 文献比较：新建项目 → 批量导入 → 查看逐文件解析状态 → 选择 2 至 8 篇文档和内置维度 → 生成矩阵 → 点击单元格 → 阅读全部证据并跳转章节 → 写笔记 → 导出 Markdown 或离线共享包。8 篇为界面默认同时可比上限，项目容量沿用 50 篇基线。

旅程 B 版本审阅：打开版本比对 → 指定旧版/新版 → 查看新增、删除、修改、移动 → 筛选变化 → 上一处/下一处定位 → 记录结论。版本比较是两份文档的文本变化，多文档比较是多份文档中研究实体与证据的对照，两者入口独立。

旅程 C 接收共享：阅读包说明 → 查看包含内容及敏感信息提示 → 离线打开报告或在正式应用导入项目 → 核对引文 → 阅读关联笔记。共享是文件传递，无在线账号、权限同步或共同编辑。

一级导航：项目概览、文档库、多文档比较、证据阅读、研究笔记、版本比对、跨文档检索（扩展预览）、离线共享、设置。项目概览展示最近任务和继续操作入口；文档库管理来源；矩阵与证据形成核心阅读闭环。独立页面共享项目标识和示例数据。

## 4 范围与优先级

P0 必须交付的产品闭环：项目管理，PDF/DOCX/MD/TXT 批量导入及解析提示，多文档内置数据集/方法对照，明确提及和使用线索，证据不足状态，Markdown 章节导航，原文定位高亮，关联笔记及 Markdown 导出，离线共享，以及既有双文档版本差异比对。P0 不要求联网或 API Key。

P1 后续增强：跨文档字面检索、过滤与结果定位；人工复核状态修订及修订历史；矩阵排序和更细的结果维度。已有应用的文件夹检索继续保留，本次设计中的统一项目检索属于扩展设计。

P2 可选探索：自定义比较维度、用户词典、OCR、经独立授权的 AI 辅助提取。自定义维度需先定义提取规则、证据要求及失败提示，不能仅添加输入框就声称支持任意语义分析。

暂不实现：实时多人协作、云同步、自动投稿、学术事实认证。离线共享不等于协作。图像、公式、表格结构和排版差异不纳入文本比较准确性承诺。

## 5 P0 功能要求与验收

### FR01 项目工作区

每个项目拥有稳定 ID、名称、说明、文档快照、比较配置和笔记。新建、打开、重命名、保存后重开应保留关联关系。删除文档需确认影响，保留笔记正文并标记来源失效。原始文件变更后旧快照不得静默替换。

验收 AC01：保存含 4 篇文档和 2 条笔记的项目后重开，文档数量、配置与引文一致；删除一篇文档后无悬空可点击引用。保存失败时保留内存内容并可重试。

### FR02 批量导入与解析

支持 PDF、DOCX、MD/Markdown、TXT，支持多选；每份独立显示待处理、解析中、完成、部分提取、失败、重复等状态。重试只处理失败项。一份失败不能撤销已成功项。按内容散列识别重复，允许同名不同内容并标出版本。默认复制快照，避免依赖原路径。

基线容量：单文件 10 MiB、正文 100000 Unicode 码点、PDF 300 页；项目 50 篇、正文合计 100 万码点。文本默认 UTF-8 含 BOM。纯扫描 PDF 提示需 OCR；加密、损坏、编码不支持或超限均提供原因。DOCX 的未提取结构必须提示，不把文本提取结果称为完整原貌。

验收 AC02：四格式文件可同时导入；重复文件提示且不增计数；损坏 PDF 不阻断其他导入；扫描件不给空文本伪成功。正文预览标注为提取文本，原貌预览不可用时可回退。

### FR03 比较配置与对照矩阵

选择至少 2 篇、默认最多 8 篇已完成解析的文档；选择数据集和/或方法。文档为列、规范化实体为行；保留别名与逐文档证据数量。共同项是同一规范项在至少两篇出现，不代表两篇均使用。区别应表达为可证实的状态或内容差别。

矩阵状态定义：使用线索＝存在采用或评测表达，尚需核对主体；仅提及＝背景或相关工作引用；明确未使用＝原文有否定证据；未发现＝当前解析范围未命中；证据不足＝命中存在但上下文、主体或解析质量不足，不能判断。一个单元格有冲突时显示“证据不足/存在冲突”，允许展开全部证据；不得只显示最强肯定结论。

验收 AC03：给定合成文档 A 明确采用、B 仅提及、C 明确否定、D 无命中，矩阵四格状态不同；损坏或部分解析不得得出“不存在”；别名合并后保留原词；不满足文档数量时禁用开始并解释原因。

### FR04 证据、章节导航与原文定位

证据保存稳定 ID、文档 ID、快照散列、章节路径、页码（如可用）、块 ID、半开字符区间和逐字引文。Markdown 章节列表使用内部锚点。点击矩阵单元格列出全部相关证据；点击证据滚动至原文并高亮，保留当前矩阵选择，支持前后项切换。

没有可靠页码时用章节与段落定位，不伪造页码。原貌坐标无法映射时明确回退提取文本。快照变化使引用失效时标记待重新定位，不静默跳到近似文本。

验收 AC04：每条引文等于对应区间；中文、emoji 与重复词场景定位正确；深层章节导航可操作；键盘可选择证据；目标离开可视区时滚动可见。导出的 Markdown 锚点在同一报告内有效。

### FR05 引用笔记

笔记包含 ID、标题、Markdown 正文、创建/修改时间及零至多条证据引用。允许无引用笔记，提供关联当前证据、编辑、显式保存、保存状态和删除。离开未保存内容时确认或提供草稿恢复。引用按证据 ID 关联，不依赖标题字符串。

验收 AC05：编辑保存并重开后正文一致；从证据创建的笔记能返回来源；删除来源后正文仍在且显示来源失效；存储失败不得显示“已保存”。

### FR06 Markdown 导出与离线共享

Markdown 报告包含项目说明、文档目录、比较维度与矩阵、状态定义、笔记、引文和章节锚点。离线 ZIP 包含 README、版本化 manifest、项目快照、report.md；原始文件默认不包含，用户明确勾选才加入 originals/。即使不附原文件，正文快照与笔记也可能包含敏感内容，导出前必须提示。

包不得包含 API Key、AI 配置、机器绝对路径。接收端限制包体积、条目数与解压量，验证散列与引用，拒绝路径穿越、重复条目、未知 schema 和越界证据；验证失败保留当前项目。HTML 报告如提供，禁止执行文档内脚本。

验收 AC06：断网在另一目录阅读报告，章节及引文内部跳转可用；正式应用可重导项目且无需原路径；带/不带原文件的内容清单准确；恶意 ZIP 拒绝。原型仅演示导出，不作为生产包格式兼容性证明。

### FR07 双文档版本比对

保留旧版、新版选择，文字视图与可用时的原貌预览，新增/删除/修改/移动分类、差异列表、前后导航、双栏定位与导出。差异用文字标签配合颜色，移动需满足可验证的文本匹配条件。未经分析的内容不显示 AI 结论。

验收 AC07：合成修订例的增加、删除、数值修改定位正确；点击第 N 项定位两侧对应文本；不能把段落移动当作研究方法差别。现有生产功能回归由应用开发任务单独执行。

## 6 扩展需求

FR08（P1）跨文档检索：限定当前项目，字面查询，结果带文档、章节和上下文，点击定位；空查询不执行，无结果提供修改查询建议。验收：检索示例词命中相符引文，不能宣称向量语义检索已实现。

FR09（P2）自定义维度：配置名称、词典/规则、可接受证据和人工确认流程。验收需建立专门标注集，报告召回及误报；本轮仅在设置中说明规划，不提供虚假可用入口。

## 7 非功能要求

NFR01 可追溯性：每项状态都可定位证据；未知与否定分开。快照和 schema 版本化。规则覆盖范围对用户可见，不将词典漏检解释为客观不存在。

NFR02 性能目标（待正式应用实测）：参考 Windows 11、4 核 CPU、16 GB 内存、SSD；20 篇各 2 万字符文本导入目标 10 秒内，矩阵计算 3 秒内，证据定位反馈 300 ms 内。解析耗时超过 1 秒应展示进度、取消及已完成结果。这些是验收目标，不是原型实测数据。

NFR03 数据与安全：默认本地处理，无隐式网络请求；原文和笔记按普通项目数据保护；正式应用保存采用临时文件与原子替换，失败可恢复。文档内容视为不可信文本，预览须转义，导出名与路径需校验。当前 HTML 演示只用于公开合成数据。

NFR04 可用性：1280 宽度下页面级无水平溢出；矩阵超列只在矩阵区横向滚动；1920 宽屏扩大阅读区；低高度允许内容区垂直滚动。正文不小于 14 px，次要标签不小于 12 px，常规按钮最小 32 px 高；焦点清晰，不只靠颜色传意；普通文本对比度目标 4.5:1。

NFR05 兼容与离线：原型在现代 Edge/Chrome 可离线打开，资源本地化；正式前端另测 Windows/macOS 的系统字体、快捷键与文件授权。浏览器 file 协议的存储隔离行为不作跨浏览器保证，建议本地 HTTP 运行。

NFR06 可维护性：CSS 设计变量、页面模板、共享数据和交互逻辑分离，ID 可映射到正式模型；记录第三方资源版本与许可。禁止把演示结论与正式研究数据混用。

## 8 数据模型与状态约束

Project：id、name、schemaVersion、documents、comparison、notes。Document：id、name、format、hash、parseStatus、warnings、blocks、headings。Evidence：id、documentId、snapshotHash、entity、state、blockId、start、end、quote。Note：id、title、body、evidenceIds、updatedAt。Comparison：documentIds、dimensions、entityRows、generatedAt、ruleVersion。

导入状态迁移：待处理 → 解析中 → 完成/部分提取/失败；重复为独立终态。比较状态：未配置 → 可开始 → 计算中 → 完成/部分完成/失败。笔记状态：已保存 → 已修改 → 保存中 → 已保存/失败。页面切换不能丢失用户已保存的数据；并发标签页修改应提示版本冲突或明确限制单窗口。

## 9 原型验收与开发交接

本次交付需包含独立页面、iframe 总览、连续操作入口、本地依赖、合成数据、Markdown/DOCX 需求文档、设计说明、生成 Prompt、截图、检查记录和 ZIP。检查覆盖 1280/1440/1920，逐页资源与脚本错误，矩阵定位、选择维度、笔记持久化、导出及共享包内容。

原型完成不代表 FR01—FR09 的正式应用实现完成。PDF/DOCX 在原型中为预置文档视图；不调用生产解析器。笔记存在浏览器，实际文件项目、通用分析、原貌定位、安全重导包和正式平台发布仍需要后端/桌面层实现。开发应按 FR 编号回填实测证据，性能与兼容性没有数据时标为待验证。

## 10 风险与待确认事项

多栏 PDF 阅读顺序、扫描件、引用主体和否定语义会降低比较可靠性，应优先呈现证据及警告。离线包含提取正文，不能把“不附原文件”称为匿名化。共享后的接收者可再次分发，无法提供远程撤回。

后续产品决策：是否允许用户修订状态并保留审计记录；macOS DOCX 原貌方案；OCR 与 AI 的成本及授权；大项目默认比较列数是否调整。本次按保守规则、人工核对与本地数据闭环设计，不以未决事项阻塞原型交付。
