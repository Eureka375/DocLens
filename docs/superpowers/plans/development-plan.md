# DocLens 开发任务清单

版本：1.0 · 2026-11-26 · 状态：计划待执行，无已完成实现或实验任务。

依据：[需求规格](../../design/requirements.md)、[技术设计](../../design/technical-design.md)、[PoC方案](../../design/poc-plan.md)。用户提供的八阶段汇总为需求基线。本次只整理文档、查看部分仓库资料，没有完成本计划中的main代码审查、技术选型或实验。

## 1. 执行规则与门槛

优先级P0=MVP必需或其验证前置，P1=正式版完善，P2=长期扩展；与痛点/用户优先级分开。计划顺序不是把晚做的F03/F04/F05降出MVP。所有任务当前“未开始”，依赖未满足时同时标“受依赖阻塞”，不把候选方案写成完成实现。

- **G0 需求与实验协议门**：四文档一致；已确认需求保留；D01/D02/D06指标口径、数据和未量化质量阈值得到相应确认。允许审查和探索，不允许把缺口当作通过。
- **G1 审查与准备门**：AUD-01、AUD-02、DATA-01、DEC-01通过；现有main基线、复用差距、数据合法性、环境/许可与实验协议明确。
- **G2 技术可行性门**：E01–E05有可复现证据且关键质量/性能/资源通过，无阈值门槛已确认；DEC-02定案。此前仅独立PoC，之后才进入DEV产品实现。
- **G3 基础设施门**：DEV-01–05及DEV-10完成必要接口、存储/任务、解析/映射、证据与索引/模型适配验证；来源、权限和恢复可用。
- **G4 MVP功能门**：DEV-01–16及PERF-01全部完成，T-F01–09、T-E2E、T-PRIVACY、T-RECOVERY通过；MVP规定深度全部可用，后续功能不冒称交付。
- **G5 发布验证门**：QA-01、QA-02、REL-01通过，全部NFR目标有实测或明确经确认的适用性结论，Windows安装/启动及无独显基础流程通过；未解决关键缺陷不得过门。发布执行与发布准备分开。

依赖字段中的G门也属于强制依赖。任务可以提前收集资料，但不得绕门全面开发。无日期工期承诺；G2后再估算。任务失败不降低阈值，需修复/换方案/复测；需求修改必须用户确认。
