# 审阅流程与AI分批覆盖验证

2026-11-22，功能基线V0.4.2 / `97806eb`。用户授权根据竞品建议实施，本轮以完整审阅流程和AI分析覆盖为交付范围，沿现有项目增量开发，无新增运行依赖，未复制竞品源码。

## 实际交付

- [review.py](../../../src/doclens/review.py)：人工核对、最多2,000字符备注、类型/状态/章节正文备注搜索，数字变化提示，独立HTML报告；内容转义、原子另存并禁止覆盖输入文件。章节位置使用二分定位，避免逐组反复扫描全部文本块。
- [app.py](../../../src/doclens/app.py)、[ReviewPane.qml](../../../src/doclens/ui/ReviewPane.qml)、[Main.qml](../../../src/doclens/ui/Main.qml)：常驻审阅清单、AI类别筛选、原编号跳转、词级高亮开关、导出入口与比较范围提示。保留原双栏和跳转，小窗口自动隐藏侧栏；原貌标记仍用精确位置。
- [analysis.py](../../../src/doclens/analysis.py)：发送前生成并验证全部批次，每批最多4组、每请求12,000字符、每任务20组/总60,000字符；单组超限拒绝，不裁剪证据。保持双侧引用校验。
- [analysis_ui.py](../../../src/doclens/analysis_ui.py)、[AnalysisDialog.qml](../../../src/doclens/ui/AnalysisDialog.qml)：一次预览全部批次并确认，顺序发送，每批120秒。显示已完成批次、等待秒数和逐组覆盖；失败/取消停止剩余队列、保留旧成功结果。合法响应遗漏的组标为未覆盖，可只补充未完成组，仍须再次预览确认。
- [test_review.py](../../../tests/test_review.py)、[test_analysis.py](../../../tests/test_analysis.py)、[test_desktop.py](../../../tests/test_desktop.py)：报告安全与原件保护、预算分批、遗漏标记、失败保留、补充授权、取消队列、筛选编号、词级跳转、真实备注输入/勾选等回归。
- [设计](../../design/2026-11-22-review-workflow.md)、[计划](../../superpowers/plans/2026-11-22-review-workflow.md)、根README、[手动案例](../../../examples/学术比较/测试指南.md)、发布说明和打包检查脚本。

## 验证结果

最终执行 `$env:QT_QUICK_BACKEND='software'; ./.venv/Scripts/python.exe -m pytest -q`，**134 passed in 15.04s**，退出码0。基线125项，本轮新增9项参数化用例。

新增核心测试先因缺失模块、控制器接口和分批函数失败，实现后通过。9组差异实际分成4+4+1；模拟第二批500时，只发送2次，保留第1批解释且第3批标记未发送；补充预览不包含前4组，确认后完成剩余5组。合法但漏组的响应显示未覆盖；取消不发后续，也不自动重试。

独立只读审查发现两项Important，均新增/加强失败测试复现后修复：

1. 重跑旧范围在收到新结果前删除旧解释。现在只在成功返回解释后合并替换，首批失败也保留全部旧结果。跨组共同解释在只重做其中部分组时保留；界面说明应结合本轮状态核对旧解释。
2. 备注失焦保存同步重置列表，导致直接勾选操作丢失。现在备注提交不重建整个列表；测试实际输入后不回车直接勾选，备注和核对标记都正确。

开发中还复现连续窗口下lambda捕获网络回复导致Qt进程abort；改回带QObject生命周期的绑定槽并校验sender后，原连续窗口回归和完整套件通过。未以关闭测试或跳过用例掩盖问题。

## 取舍与后续

本轮借鉴的是审阅流程和可追溯分析设计，不主张独有能力或优于竞品的准确率。无OCR、复杂PDF阅读顺序/表格模型、公式图像变化检测、通用改写移动或Word插件；后续需独立数据集和安装体积评估。当前备注/核对状态仅在本次比较中保留，换文档或重比会清空，可通过HTML留档；尚无审阅会话恢复。实际模型连通性、响应时延及解释正确率仍需用真实服务和人工标注案例验收。
