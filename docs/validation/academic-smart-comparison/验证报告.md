## 验证方法与指标

执行 `$env:QT_QUICK_BACKEND='software'; ./.venv/Scripts/python.exe -m pytest -q`，完整输出见[测试日志](pytest.txt)。

- 全套最终 **110 passed in 10.67s**，退出码0；基线75项，本轮新增35项。最终结果包含独立审查问题的6项回归。
- DOCX/PDF/TXT 全部9种格式组合：解析→章节→Diff→AI草稿→结构化响应校验→原文范围核对；9/9通过，源文件字节未变。
- 自动化界面实际点击选择JSON格式、预览、确认发送并验证请求；无效单侧引用被拒绝，随后仍可跳至第5组“90”。
- 模拟401、402、429、302、500：保留5组本地差异并可跳转。真实服务器、TLS链和模型准确性不由模拟服务覆盖。
- 新增核心行为先运行失败测试再实现；章节发送预览缺漏和审查问题也按失败→修复验证。
- 独立只读代码审查发现1项重要问题：小样本数/带单位小数被误识别为标题。补充6项失败测试后，将推断收紧到已知学术标题词表；此取舍会漏掉自定义提纲，但正文仍参与比较。
- 演示案例实测为3组：30→60、单次划分→五折交叉验证、91.5→93.2。
- `git diff --check` 检查空白错误；换行符转换提示属于仓库Windows设置。

这些是确定性样例和模拟协议指标，不是语义准确率、召回率或真实性保证。引用校验只确认ID、两侧完整性和本地范围，不能证明解释符合科学事实。
